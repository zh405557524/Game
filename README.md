# Game

这是一个用于游戏开发的统一工作区，集中管理游戏工程、策划文档、原始素材、工具和测试资料。

## 目录结构

```text
Game/
├── game/                 # 游戏引擎工程与运行时代码
├── docs/
│   ├── 00_项目总览/      # 立项、范围与跨领域交付流程
│   ├── 01_游戏底层架构/  # 世界模拟框架与运行规则
│   ├── 02_界面交互与表现/# 玩家体验、界面 PRD、设计稿与原型入口
│   ├── 03_美术风格/      # 水墨规范、设计方案与资源生产
│   ├── 04_Unity实现/     # Unity 工程、表现方案、场景与验收
│   ├── 05_代码框架搭建/  # 技术架构、数据结构与程序集边界
│   └── 90_资料与归档/    # 有效历史资料、参考与冻结证据
├── assets/
│   ├── art/              # 概念、角色、场景、UI、特效原始素材
│   ├── audio/            # 音乐、音效、配音原始素材
│   ├── fonts/            # 字体及授权说明
│   ├── video/            # 宣传片、过场等视频源文件
│   ├── localization/     # 本地化源表与术语表
│   └── licenses/         # 第三方素材许可证与来源记录
├── tools/                # 构建、导入、转换、检查等辅助工具
├── tests/                # 跨模块、集成与自动化测试资料
├── third_party/          # 必须随仓库管理的第三方依赖及说明
└── builds/               # 本地构建产物，不提交 Git
```

## 使用约定

1. 选定 Unity、Unreal、Godot 或其他技术方案后，将完整引擎工程放进 `game/`，不要再增加一层同名仓库。
2. 可编辑的素材源文件放在 `assets/`；导入引擎后的运行时资源遵循对应引擎目录结构，避免维护两份相同导出文件。
3. 单个大型二进制文件进入仓库前先配置 Git LFS；不要直接提交构建包、缓存、临时文件或密钥。
4. 文件和目录统一使用有意义的英文名称；建议目录使用 `kebab-case`，代码遵循所选引擎或语言规范。
5. 文档从 `docs/README.md` 进入；重大规则、表现和工程决策分别维护在对应职责区，避免建立第二份权威正文。

## 开发前需要确定

- 游戏类型、核心循环和目标玩家
- 首发平台、屏幕方向、最低设备规格
- 游戏引擎及固定版本
- 单机/联网模式、账号与存档策略
- 首个可玩原型的范围和验收条件
- 大型素材的 Git LFS 与备份策略

# 全国分时月结负载诊断

独立、可复现的 **合成压力测试**。不安装软件，不修改历史库、游戏源码或正式存档，不代表已经接入 Unity 月结。

## 运行

```bash
python3 tools/settlement_benchmark/run.py
```

默认使用本机 Unity `6000.5.10f1` 自带的 `.NET 8 SDK`，无外部 NuGet 依赖，Release 构建。
其他安装位置可传 `--dotnet /absolute/path/to/dotnet`。可指定 `--database` 与 `--output`。

默认输出到 `builds/settlement-benchmark/`：`fixture.json`、`results.json`、`metadata.json`、`report.md` 和编译产物。重复运行会更新此专用目录的同名输出。

## 输入与负载

- 从 v1.0 SQLite 用只读连接提取真实县、计算区 ID 和人口，核对逐县人口守恒，并比较运行前后数据库 SHA-256。
- 地理结构为真实项目数据；人物、人口群体、关系、经济存量与流量全部为合成，不当成史实或完整玩法。
- 常规档：每县 12 名官员、额外 10 万人物、每区 12 个人口群体、29 个资源槽。
- 加重档：每县 24 名官员、额外 30 万人物、每区 24 个人口群体，增加候选数、关系读取、外力驱动和跨县交易。
- 生产阶段编译并调用现有 `ProductionSettlementService`；其余负载使用显式的简化合成规则。

## 测量与校验

同一输入比较同步执行、2ms 预算分片、独立批次反向顺序、约 60Hz 无画面节拍、两处检查点 JSON 恢复的完整状态摘要。
检查人口/资源/资金守恒、父级归属、月结重复发布、跨月预留命令、超支拒绝、损坏数据拒绝。

分片时间之外，单独报告初始化、月结数组分配、完整审计、摘要和检查点序列化耗时。2ms 是协作预算，不能保证最慢分片不超时。

没有 Unity 渲染、完整 AI/寻路/贸易撮合、存档数据库写入、断电恢复、真实多线程；不能据此声称整款游戏不卡顿。报告列出实际覆盖和未覆盖范围。
